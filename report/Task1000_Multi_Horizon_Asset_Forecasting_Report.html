Task 1000: Multi-Horizon Asset Price Forecasting

Full Project Report

This report documents the complete workflow of Task 1000, from historical market data preparation and exploratory analysis to financial feature engineering, multi-horizon forecasting, model comparison, uncertainty analysis, and final price estimates.

The project focuses on Tesla (TSLA), Alphabet (GOOGL), Bitcoin (BTCUSD), Ethereum (ETHUSD), and QQQ. The analysis is designed to compare equity and cryptocurrency market behaviour across multiple forecasting horizons.

1. Project Objective

The objective of this project is to forecast the future prices of TSLA, GOOGL, BTCUSD, and ETHUSD across seven horizons: 30 days, 3 months, 6 months, 1 year, 3 years, 5 years, and 10 years.

Two forecasting approaches will be compared: ARIMA as a traditional time-series benchmark and Random Forest Regressor as a feature-driven machine learning model.

The project also incorporates momentum and mean reversion analysis, volatility regime analysis, and Monte Carlo simulation to assess forecast uncertainty and cross-asset differences.

2. Data Sources

Historical daily market data were collected from the following sources:

  • TSLA: Stooq
  • GOOGL: Stooq
  • QQQ: Stooq
  • BTCUSD: Stooq
  • ETHUSD: CoinMarketCap

The datasets contain daily Open, High, Low, Close, and Volume information where available. BTCUSD from Stooq does not include a Volume field, so volume-based features are treated as optional for that asset.

5. Forecasting Indicators and Methodology

Following the exploratory analysis, a set of financial indicators is constructed to capture recent return behaviour, momentum, trend conditions, volatility, and market-relative performance.

These indicators are used as explanatory features in the Random Forest model, while ARIMA provides a separate univariate time-series benchmark based primarily on the historical price dynamics of each asset.

This section introduces the purpose of each forecasting indicator, explains how future return targets are constructed across multiple horizons, and defines the evaluation metrics used to assess model performance.

5.1 Daily Return

Daily return measures the percentage change in an asset's closing price from one observation to the next and provides the most basic measure of short-term price movement.

Formula:

Daily Return = (Current Close / Previous Close) - 1

Daily return is included as a forecasting feature because recent price movements may contain information about short-term continuation, reversal, or changing market conditions. However, individual daily returns are highly noisy and are therefore interpreted together with momentum, trend, volatility, and market-relative indicators rather than being used as a standalone forecasting signal.

The Random Forest model uses simple percentage returns, while the ARIMA framework uses log prices and first-differenced log returns for time-series stationarity analysis. This distinction reflects the different roles of returns in the two forecasting approaches.

5.2 Momentum Indicators

Momentum indicators measure the cumulative price change over different historical lookback windows. Unlike daily return, which captures only the most recent one-period movement, momentum describes whether a broader short- or medium-term price trend has developed.

Formula:

Momentum(n) = (Current Price / Price n observations ago) - 1

Indicator Lookback Purpose
Momentum 5D 5 observations Captures very short-term price direction.
Momentum 20D 20 observations Measures a broader short-term trend.
Momentum 60D 60 observations Captures more persistent medium-term price behaviour.

Using multiple momentum horizons allows the model to distinguish recent price movements from more persistent trends. For example, positive 60-day momentum combined with negative 5-day momentum may indicate a short-term correction within a broader upward trend.

Momentum indicators are included because recent trends may persist when market information is incorporated gradually into prices. However, strong momentum can also indicate that an asset has become temporarily overextended and may subsequently experience mean reversion. Momentum is therefore interpreted together with moving-average, volatility, and market-relative features rather than as a standalone trading signal.

5.3 Moving-Average and Mean-Reversion Indicators

Moving-average indicators compare the current asset price with its recent average price level. They are used to assess whether the asset is trading close to, above, or below its recent trend.

Formula:

Price-to-MA(n) = Current Price / n-period Moving Average

Indicator Reference Window Purpose
Price-to-MA20 20 observations Measures the current price relative to a shorter-term average level.
Price-to-MA60 60 observations Measures the current price relative to a broader medium-term trend.

A value above 1 indicates that the current price is above its recent average, while a value below 1 indicates that it is trading below that average. This can contain information about both trend continuation and potential mean reversion.

For example, a price moderately above its moving average may indicate an established upward trend, while an unusually large deviation from the recent average may suggest that the asset has become temporarily overextended and could subsequently revert toward its historical mean.

These indicators complement momentum features because momentum measures the cumulative price change over a historical window, whereas Price-to-MA measures the current price's position relative to the average level observed during that window. Together, they provide the Random Forest model with information about both trend direction and the degree of price deviation.

5.4 Rolling Volatility

Rolling volatility measures the recent variability of asset returns and is used to describe changes in short-term market risk. Unlike return and momentum indicators, volatility does not directly measure price direction; instead, it captures the magnitude and instability of recent price movements.

Calculation:

Rolling Volatility (20D) = Standard Deviation of Daily Returns over the most recent 20 observations

A rolling window is used because market volatility is not constant through time. The exploratory analysis showed repeated transitions between relatively calm and highly volatile periods across all selected assets, indicating clear volatility clustering. Cryptocurrency assets and TSLA generally exhibited larger volatility fluctuations than GOOGL and QQQ.

The 20-observation window provides the model with a measure of the current market risk environment. For equity assets, this window corresponds approximately to one trading month, while for cryptocurrency assets it represents 20 consecutive daily observations.

Volatility can also change the interpretation of other forecasting indicators. For example, strong positive momentum during a low-volatility period may represent a relatively stable trend, whereas the same momentum during a high-volatility period may reflect a more unstable market move. Rolling volatility is therefore used together with momentum and moving-average indicators rather than as a standalone directional signal.

Rolling volatility is backward-looking and reflects only recently observed market behaviour. A low recent volatility level does not guarantee that future volatility will remain low, particularly when new information or market shocks occur.

5.5 Market-Relative Indicators

For the equity assets, QQQ is used as a growth-oriented market benchmark to provide information about broader market conditions and relative stock performance. These features are included for TSLA and GOOGL but not for BTCUSD or ETHUSD.

Indicator Calculation Purpose
QQQ Return Daily percentage return of QQQ Captures broader growth-equity market movement.
Excess Return vs QQQ Asset Return - QQQ Return Measures asset performance relative to the benchmark.

QQQ return provides market context. For example, a positive TSLA or GOOGL return may have a different interpretation when the broader growth-equity market is also rising than when the benchmark is declining.

Excess return helps distinguish market-driven price movements from relative outperformance or underperformance. A large positive excess return indicates that the asset has performed more strongly than QQQ during the same observation period.

These market-relative features are particularly relevant because the exploratory analysis showed meaningful relationships between the equity assets and QQQ, especially for GOOGL. However, QQQ is only a simplified market benchmark and does not capture all macroeconomic, sector-specific, or company-specific influences on equity returns.

QQQ-relative features are not applied to BTCUSD and ETHUSD because the exploratory analysis showed substantially weaker relationships between the equity and cryptocurrency groups.

5.6 Forecast Targets and Horizons

The forecasting models are designed to predict cumulative future returns rather than future prices directly. Using returns provides a standardized target across assets with substantially different price levels and allows model errors to be interpreted on a comparable percentage basis.

Future Return Target:

Future Return(t,h) = Future Price(t,h) / Current Price(t) - 1

Price Reconstruction:

Predicted Future Price = Current Price × (1 + Predicted Future Return)

Forecast Horizons

Model Forecast Horizons Role
Random Forest 30D, 3M, 6M, 1Y, 3Y, 5Y, 10Y Tests feature-driven forecasting relationships across short and long horizons.
ARIMA 30D, 3M, 6M Provides a traditional short- and medium-horizon time-series benchmark.

Calendar-Based Target Alignment

Forecast horizons are defined using calendar time rather than fixed row counts. For each observation, the target date is calculated by adding the required calendar horizon to the current date. The nearest available market observation on or after that target date is then used as the realized future price.

This approach is particularly important when comparing equities and cryptocurrencies. Equity markets do not trade on weekends or market holidays, while cryptocurrency markets operate continuously. A fixed observation shift would therefore represent different calendar horizons across the two asset classes.

Chronological Splitting and Leakage Prevention

All forecasting models preserve chronological order so that historical observations are used to predict later market outcomes. Random shuffling is avoided because it could allow future market information to enter the training sample.

Additional target purging is applied to the Random Forest training data. A training observation is retained only when both its feature date and its corresponding future target date occur before the train-test split. This prevents future prices from the test period from being indirectly used during model training.

Longer forecasting horizons naturally produce fewer usable observations because data near the end of the historical sample may not contain a sufficiently distant realized future price. For very long horizons, insufficient historical coverage may prevent leakage-safe model estimation altogether.

5.7 Forecasting Models

Two forecasting approaches are used to examine whether future asset returns can be predicted from different forms of historical market information. Random Forest provides a feature-driven machine learning model, while ARIMA serves as a traditional univariate time-series benchmark.

Random Forest Regressor

Random Forest combines multiple decision trees to learn potentially nonlinear relationships between current financial indicators and future cumulative returns. Each tree partitions the historical observations according to different combinations of features, and the final prediction is obtained by averaging predictions across the ensemble.

This structure is useful because financial indicators may interact in nonlinear ways. For example, positive momentum may have a different forecasting implication during a low-volatility trend than during a highly volatile and potentially overextended market move.

Random Forest Specification:

Number of Trees = 300
Maximum Tree Depth = 8
Minimum Samples per Leaf = 5

The specification is used as a controlled benchmark rather than an optimally tuned model. Tree depth and minimum leaf size are restricted to reduce excessive model complexity and overfitting.

ARIMA

ARIMA models future price behaviour using the historical time-series dynamics of each asset rather than the broader feature set used by Random Forest. The model is represented as ARIMA(p,d,q), where p captures autoregressive dependence, d represents the order of differencing required for stationarity, and q captures dependence on previous forecast errors.

Log prices are first tested for stationarity using the Augmented Dickey-Fuller test. When the price series is non-stationary but the first-differenced log-price series is stationary, the integration order is set to d = 1. ACF and PACF analysis, together with AIC and BIC model-selection criteria, are then used to identify reasonable candidate specifications.

ARIMA forecasts are evaluated using a walk-forward framework. As the evaluation period progresses, newly observed market information is added to the model history and model parameters are periodically re-estimated. This approach more closely represents a real-time forecasting process than generating all future forecasts from a single historical endpoint.

Model Comparison

Dimension Random Forest ARIMA
Model Type Machine learning ensemble Traditional time-series model
Main Input Multiple financial indicators Historical asset price series
Relationship Nonlinear Linear time-series dependence
Forecast Target Future cumulative return Future log price and reconstructed return
Forecast Horizons 30D, 3M, 6M, 1Y, 3Y, 5Y, 10Y 30D, 3M, 6M
Primary Role Feature-driven forecasting model Traditional benchmark model

Using both approaches allows the analysis to test whether a broader set of financial indicators provides predictive information beyond the asset's own historical time-series structure.

5.8 Evaluation Metrics

Forecast performance is evaluated using multiple metrics because no single measure fully describes prediction quality. The evaluation considers forecast magnitude, sensitivity to large errors, explanatory performance, directional accuracy, and improvement relative to a simple no-change benchmark.

Metric Purpose Interpretation
MAE Measures the average absolute difference between predicted and realized future returns. Lower values indicate smaller average forecast errors.
RMSE Measures forecast error while placing greater weight on large prediction mistakes. Lower values indicate better performance, particularly when large errors matter.
R² Compares squared forecast errors with a predictor based on the mean realized return. Positive values indicate improvement over the mean-target comparator; negative values indicate worse performance.
Directional Accuracy Measures how often the model correctly predicts whether the future return is positive or negative. Higher values indicate better directional classification, but do not measure forecast magnitude.
Baseline Improvement Measures the reduction in MAE or RMSE relative to a zero-return benchmark. Positive values indicate that the forecasting model outperforms the baseline.

Zero-Return Baseline

A zero-return benchmark is used to determine whether each forecasting model adds predictive value beyond a simple no-change assumption. The baseline always predicts a future return of zero, implying that the future price is equal to the current price.

Baseline Prediction:

Predicted Future Return = 0

Error Improvement:

Improvement = Baseline Error - Model Error

Positive Improvement → Model outperforms the baseline
Negative Improvement → Model underperforms the baseline

MAE and RMSE are used as the primary measures of return-magnitude forecasting accuracy. R² provides an additional comparison against a mean-return predictor, while directional accuracy evaluates whether the model correctly identifies the sign of future returns.

Directional accuracy should not be interpreted independently of the return distribution. If most observations within a forecast horizon have the same return sign, a model may achieve high directional accuracy without providing meaningful magnitude forecasting ability.
